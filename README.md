# 電子貓日記

一個極簡的個人情緒與生活紀錄 PWA，裡面住著一隻電子貓。不是醫療 App、不是心理諮商 App、不是任務管理 App——核心只有一件事：**隨時把正在發生的事情記下來，慢慢看見自己的情緒、第一反應與處理方式。** 電子貓只是陪伴與輕量遊戲化元素。

Mobile-first：主要使用裝置是 iPhone Safari / iPhone PWA，Desktop 只是「可以用」。

## 使用技術

- [Next.js](https://nextjs.org/)（App Router）+ TypeScript + Tailwind CSS
- IndexedDB（`idb`）做為唯一本機資料儲存，不使用 localStorage 存音檔
- MediaRecorder API 錄音、Pointer Events 拖曳（家具與貓咪，觸控/滑鼠通用）
- Google Gemini API（免費額度，語音轉文字，唯一會呼叫外部服務的功能）
- Resend（每日提醒 Email）+ Vercel Cron
- PWA（manifest、iOS safe-area、可加入主畫面）
- WebAuthn（Face ID / Touch ID，若裝置支援）+ PIN 作為隱私鎖

除了語音轉文字之外，儲存日記後也會安靜地呼叫一次 AI（同一組 Gemini 免費額度），整理這一篇的情緒摘要；只送出這一篇的文字內容，不是心理諮商、不做診斷，詳見下方「AI 的定位」。「需要 AI 幫忙？」則是另一個獨立功能：本機組字生成 Prompt，你自己複製貼到平常用的 AI。

## 功能列表

- **首頁**：只有自由走動的貓、[📝 記錄今天]、[記錄吃藥]，貓咪可以走到整個首頁任何地方（包含按鈕上面），輕點互動、雙擊叫過來、按住可拖曳
- **記錄今天**：可選日期（今天或今天以前，用於補記過去幾天），先選 🎙️錄音 或 ✏️文字記錄；錄音是單一入口（綁定「發生了什麼事」），錄完手動按「轉換成文字」才轉錄，原始音檔永久保留；其餘 5 個欄位（第一反應／實際情緒／想做什麼／表現出來的心態／最後怎麼處理）都是純文字、全部非必填；同一頁也可以標記選定日期的吃藥狀態。一天可建立無限筆
- **事件詳情**：「現在回頭看」（當下 vs 事後）、「預期 vs 實際」；存檔立即完成，不會等 AI；AI 情緒摘要會在背景整理好後安靜地出現在同一頁（情緒／次要情緒／強度／摘要），未設定金鑰或整理失敗時顯示「尚未整理」，不會假裝成功
- **需要 AI 幫忙？**：次要功能，需要使用者主動點「整理成 Prompt」，把這筆（或這個月／過去 30 天）紀錄組成一段可以直接複製貼到 ChatGPT / Claude 等你平常用的 AI 的文字；這個功能本身不呼叫任何 AI、不評價、不給建議
- **2 分鐘陪伴**：在「記錄今天」裡開啟，計時器與錄音完全獨立，不說話也能完成，沒有獎勵也沒有懲罰機制
- **狀況頁**：月曆為主視圖（可切換月份，月份/星期列會 sticky 在上方），每格用小圓點顯示當日整體心情、空心圓顯示吃藥狀態；點日期看當天詳情（今日情緒、次要情緒、情緒強度、AI 整理的當日摘要）、可手動修改當日整體心情（一旦手動設定就不會被自動計算覆蓋，且使用者標記的情緒永遠優先於 AI）；下面是本月摘要、最近的我（過去 30 天）、需要留意
- **回顧頁**：依日期列出歷史紀錄（語音／文字），可以點進去播放原始錄音、查看 Transcript，也可以搜尋紀錄裡的文字
- **需要留意**：本地關鍵字安全網 + AI 摘要時偵測到的明確自我傷害／輕生語句，偵測到才會安靜標示，不會彈窗、不下診斷、不猜測
- **匯出紀錄（醫師報告）**：可選 7天/30天/自訂區間，內容為情緒分布、需要留意、文字轉錄、選擇性語音索引（不含原始錄音檔），用瀏覽器「列印/另存 PDF」輸出
- **貓咪狀態**：吃藥已記錄時保持醒著；過了每日提醒時間仍未記錄，貓咪會安靜休息（不代表「沒吃」，只代表今天還沒確認），一補記就會醒來
- **吃藥紀錄**：單純的已記錄/尚未記錄切換，不含劑量、不做藥物建議，可補登過去日期；沒有記錄的日子一律顯示「尚未記錄」，不會顯示「沒吃」
- **隱私鎖**：PIN（SHA-256 本機雜湊）+ 若裝置支援可加開 Face ID / Touch ID
- **資料管理**：匯出/匯入 JSON（含音檔）、清除所有資料
- **每日提醒 Email**：每天 22:00（台北時間）提醒「記錄一下今天」，不含情緒/吃藥/日記內容

## 本機開發

```bash
npm install
npm run dev
```


## Environment Variables

複製 `.env.example` 為 `.env.local`：

```bash
cp .env.example .env.local
```

`.env.local` 已加入 `.gitignore`，不會被 commit。未設定對應金鑰時，該功能會在介面顯示「尚未設定」，不會假裝成功。

| 變數 | 用途 |
| --- | --- |
| `GEMINI_API_KEY` | 語音轉文字（`/api/stt`）與日記情緒摘要（`/api/analyze`）共用同一組 Google Gemini 免費額度金鑰——這是整個 App 唯一需要的 AI 相關金鑰 |
| `RESEND_API_KEY` | 每日提醒信 |
| `RESEND_FROM_EMAIL` | 寄件地址（未驗證網域時用 `onboarding@resend.dev`） |
| `REMINDER_EMAIL_TO` | 覆寫提醒信收件人 |
| `APP_URL` | 提醒信中「記錄今天」按鈕連結的網域 |
| `CRON_SECRET` | 保護 `/api/email/send` 不被任意觸發 |

### Speech-to-Text 設定

1. 到 https://aistudio.google.com/apikey 免費建立 `GEMINI_API_KEY`（Google 帳號登入即可，免信用卡），用於 `/api/stt`，這是唯一會把使用者內容送到外部服務的功能，且只有在使用者主動按下「轉換成文字」時才會送出。
2. 金鑰是 server-side 呼叫，不會出現在前端程式碼或瀏覽器網路請求中。
3. 未設定金鑰時，錄音跟播放仍正常運作，只是不會自動產生文字，使用者可以自己手動輸入。

### AI 的定位

這個 App 的 AI 情緒摘要（[`src/lib/aiAnalysis.ts`](src/lib/aiAnalysis.ts)、[`src/app/api/analyze/route.ts`](src/app/api/analyze/route.ts)）是安靜的**反思／整理工具**，不是心理治療師，也不是聊天機器人：

- **不診斷**：不判斷、不暗示任何精神疾病或心理狀況，不對藥物或醫療做任何判斷或建議。
- **不猜測**：只根據使用者實際寫出／說出的文字整理，內容不足時對應欄位是 `null`（介面顯示「無法判斷」或「尚未整理」），不會腦補沒寫出來的事。
- **使用者優先**：日記裡的「實際情緒」與狀況頁的每日整體心情，只要使用者自己手動選過，永遠不會被 AI 的結果覆寫——AI 只在使用者沒有手動標記時補位。
- **絕不碰吃藥紀錄**：AI 分析的輸入輸出都只在 `events` 這個 store 裡，完全不會讀取或寫入 medication 資料，也不會從日記內容推測「今天有沒有吃藥」。
- **不阻塞儲存**：錄音／文字存檔一律先完成（音檔、Transcript、手打文字、使用者手動 Mood、Event 都會先落地），AI 整理是存檔後才觸發的背景呼叫，失敗或逾時只會讓對應欄位顯示「尚未整理」，不影響已存的紀錄。
- **只送當下這一筆**：每次呼叫只送出這一篇日記自己的文字（或狀況頁單日摘要時，只送出當天幾篇已經整理過的短摘要），不會送出整個 IndexedDB、其他日期的紀錄、音檔或 Medication。
- **安全字詞留意**：只有在文字出現非常明確、直接的自我傷害／輕生語句時才會標記「需要留意」（沿用既有的 [`src/lib/safetyCheck.ts`](src/lib/safetyCheck.ts) 本地關鍵字機制的同一個欄位），一般的抱怨、疲累、生氣不會被誤判；標記只會安靜出現在事件詳情與狀況頁，不會在首頁跳出警告，也不會做任何診斷。
- **不主動聊天**：AI 不會主動跳出建議或對話。如果需要更完整的建議，「整理成 Prompt」（[`src/lib/aiPrompt.ts`](src/lib/aiPrompt.ts)）仍然是把紀錄組成文字讓使用者自己複製貼到平常用的 AI，兩者是完全獨立的功能。

情緒分布、每日整體心情這些統計仍然是 [`src/lib/stats.ts`](src/lib/stats.ts) 裡的本地邏輯，只是現在「當天整體心情」在使用者沒有手動標記某一篇的情緒時，會把該篇的 AI 分析結果也一併納入多數決（同樣，使用者手動標記優先）。

### Email Reminder 設定

1. 到 https://resend.com/ 建立帳號與 `RESEND_API_KEY`。
2. 設定 `RESEND_FROM_EMAIL`（建議驗證自己的網域；測試階段可用 Resend 提供的 `onboarding@resend.dev`，但只能寄到你自己 Resend 帳號的信箱）。
3. 部署到 Vercel 後，`vercel.json` 內建的 Cron 會在每天 14:00 UTC（= 22:00 Asia/Taipei，台灣不使用日光節約時間，全年固定）呼叫 `/api/email/send`。
4. 在 Vercel 專案設定 `CRON_SECRET`，Vercel Cron 會自動帶上相同的值，避免路由被任意觸發、重複寄送。
5. 「設定」頁面有「寄送測試 Email」按鈕，可獨立於每日排程手動測試。

## PWA 使用方式

1. 用 iPhone Safari 開啟部署後的網址。
2. 點擊「分享」→「加入主畫面」。
3. 從主畫面圖示開啟，會以全螢幕 standalone 模式顯示（沒有網址列），並正確處理 Safe Area / Dynamic Island / Home Indicator。
